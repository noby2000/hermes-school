🩺 Hermes тупит или «кончились токены»: как проверить за 2 минуты

Если Hermes вдруг стал отвечать медленно, глупо или пишет, что «кончились токены», не паникуй. Чаще всего дело не в токенах, а в связи. Вот как это быстро проверить. Все команды запускай в терминале Ubuntu (WSL), просто копируй их целиком.

Как всё устроено: Hermes → твой OmniRoute (127.0.0.1:20128) → цепочка free-chain (с 21 октября): OpenRouter minimax-m3.1-flash:free → Z.ai GLM-4.5-Flash → OpenRouter Nemotron → Groq → NVIDIA → Gonka MiniMax-M2.7 → Gonka DeepSeek-V4-Flash → Gonka GLM-5.3-Flash. Без VPN из России сейчас отвечает только Z.ai — он медленнее и слабее, но для спецификаций и коммитов хватает. Если первая модель недоступна, цепочка сама уходит на Z.ai — поэтому Hermes вроде отвечает, но «тупит».

1. Живы ли службы?

Проверяем, что OmniRoute и Hermes-шлюз запущены:

systemctl --user is-active omniroute hermes-gateway

✅ Хорошо — два раза active. ❌ Плохо — inactive или failed. Тогда перезапусти:

systemctl --user restart omniroute hermes-gateway

и через 10 секунд проверь ещё раз.

2. Какая модель на самом деле ответила?

Самый простой способ — открой панель OmniRoute http://127.0.0.1:20128 (пароль в файле ~/.omniroute-credentials) и посмотри журнал запросов (Request logs / Logs): там видно, какой провайдер и модель ответили, и какие упали с ошибкой.

Или быстрая проверка из терминала. Первая строка загружает твои ключи из ~/.hermes/.env (на экран они не выводятся), вторая отправляет в OmniRoute «привет» и показывает только название модели:

set -a; . ~/.hermes/.env; set +a
curl -s http://127.0.0.1:20128/v1/chat/completions -H "Authorization: Bearer $OMNIROUTE_API_KEY" -H "Content-Type: application/json" -d '{"model":"free-chain","messages":[{"role":"user","content":"привет"}],"max_tokens":20}' | grep -o '"model":"[^"]*"'

✅ Хорошо — первая модель цепочки (MiniMax). ⚠️ Если там glm-4.5-flash — значит OpenRouter не отвечает, и почти всегда причина в том, что VPN выключен. Переходи к шагу 3. ❌ Если вообще ничего не вывелось — убери | grep ... в конце и посмотри, какую ошибку пишет OmniRoute.

3. Доходит ли интернет до провайдеров?

Стучимся по очереди в Gonka, OpenRouter и Z.ai (только IPv4, ждём до 10 секунд) и смотрим код ответа:

for u in https://proxy.gonkabroker.com/v1/models https://openrouter.ai/api/v1/models https://api.z.ai; do curl -4 -s -o /dev/null -m 10 -w "$u %{http_code}\n" $u; done

✅ 200, 301, 401 — сайт доступен (401 тут нормально: мы просто не отправляли ключ). ❌ 000 — связи нет совсем: включи VPN (Happ) или проверь, что он не отвалился, и повтори. Если 000 только у Gonka и OpenRouter, а у Z.ai нормальный код — точно дело в VPN.

4. Токены правда кончились?

Проверяем лимит ключа OpenRouter (сначала выполни строку set -a; . ~/.hermes/.env; set +a из шага 2, если открыл новый терминал). Команда покажет только расход и лимит, без ключа:

curl -s https://openrouter.ai/api/v1/key -H "Authorization: Bearer $OPENROUTER_API_KEY" | grep -o '"\(usage\|limit\|limit_remaining\|is_free_tier\)":[^,}]*'

У бесплатных моделей OpenRouter есть дневной лимит запросов, он сбрасывается в 03:00 по Москве. Баланс Gonka (1 млн бесплатных токенов в месяц) смотри в личном кабинете Gonka Broker.

Что значат коды ошибок (их видно в журнале OmniRoute или в ответе без grep):

КодЧто значитЧто делать

402Нужны деньги / закончился балансПополнить или убрать провайдера из цепочки
401 / 403Неправильный или выключенный ключ, или блокировка регионаПроверить ключ в панели провайдера (не «на паузе» ли), включить VPN

Hermes умеет проверять себя сам — настройки, ключи, модели:

Разбор ошибок (чему научились)

Ошибки — это нормально, у всех разработчиков они бывают. Главное — понять, почему так вышло. Вот что мы нашли и починили:

1. Опечатка в config.yaml

В файле было plreasoningugins: вместо plugins: — из-за этого ломался раздел плагинов. Урок: настройки меняй через hermes config и hermes model, а не руками; перед ручной правкой делай копию (cp ~/.hermes/config.yaml ~/.hermes/config.yaml.bak); после правки запускай hermes doctor.

2. Ключи в .env без имени

Ключи были вставлены в ~/.hermes/.env голой строкой — Hermes их не видит. Правильный формат — имя переменной, знак «=» и значение: 

ИМЯ_API_KEY=значение
Например OPENROUTER_API_KEY=.... Проще всего вводить ключ через hermes model — он сам запишет как надо.

3. Ключи нельзя показывать

Ключ — как пароль от кошелька. Никогда не пересылай его в чатах, не показывай на скриншотах и не клади в GitHub. Если ключ засветился — сразу удали его у провайдера и создай новый (перевыпусти).

4. Kimi: ошибка 401 и зависания

Ключ от международной платформы (moonshot.ai) был прописан на китайский адрес (moonshot.cn) — сервер отвечал 401 («не авторизован»). А ещё на счёте был ноль, аккаунт приостановили, и Hermes зависал на каждом ответе. Урок: проверь, что у провайдера есть баланс или бесплатный лимит, и что адрес (base URL) совпадает с той платформой, где ты брал ключ.

5. Groq: ошибка 413

Бесплатных лимитов Groq (около 7–8 тысяч токенов в минуту) мало для Hermes — один запрос агента больше, отсюда ошибка 413. А модель gpt-oss ругается на настройку reasoning_effort, если там не low/medium/high. Урок: для агента важны лимиты провайдера, а не только «бесплатно».

6. Что работает из России без VPN

OpenRouter, NVIDIA, Groq и Gemini из России отвечают отказом (403, 451 или «location not supported»). SambaNova просит привязать карту. Без VPN работает Z.ai — поэтому он основной. С VPN вариантов больше, но VPN Happ мешает удалённой помощи (tmate, Tailscale) — на время помощи его надо выключать.

7. Бесплатная модель бывает перегружена

Бесплатная GLM-4.7-Flash иногда отвечает ошибкой 429 («слишком много запросов») или думает по 1,5–2 минуты. Поэтому основная модель — GLM-4.5-Flash, а для всех ролей настроены запасные. Урок: всегда держи запасной вариант.

8. Vercel, Supabase, Firebase — не для нас

Hermes предлагал эти сервисы, но для российского приложения их использовать нельзя: по 152-ФЗ персональные данные россиян нужно хранить в России. Наш выбор — Yandex Cloud, Selectel или Timeweb Cloud + PostgreSQL. Урок: агент знает много, но законы РФ проверяй сам — и проси агента учитывать их прямо в задаче.

9. Сломанный IPv6 в WSL — запросы зависали

DNS отдавал IPv6-адреса, но IPv6 в Ubuntu не работал — и запросы к моделям просто висели без ответа. Починили одной командой, теперь система сначала пробует IPv4: 

echo 'precedence ::ffff:0:0/96  100' | sudo tee -a /etc/gai.conf
Урок: если curl к сайту зависает, а ya.ru в браузере открывается — попробуй curl -4 .... Если с -4 работает, виноват IPv6.

10. Два раза skills: в config.yaml — Hermes не запускался

При подключении навыков OpenSpec блок skills: дописали в конец ~/.hermes/config.yaml два раза подряд. Hermes отказался стартовать с ошибкой «duplicate key skills». Мы убрали дубль и вписали папку навыков в уже существующий блок. Урок: в YAML каждый ключ должен быть один. Не дописывай блок в конец файла — найди существующий и поправь его. После правки проверь hermes config check и hermes doctor. И всегда делай копию перед правкой: cp ~/.hermes/config.yaml ~/.hermes/config.yaml.bak.

11. VPN Happ рвёт связь

Когда Happ отключался или переключал сервер, в Ubuntu пропадал интернет целиком, а заодно и Tailscale — папа терял связь посреди настройки. Урок: в Happ включи раздельное туннелирование (split tunneling) и добавь Tailscale в исключения — тогда VPN и удалённая помощь не мешают друг другу.

12. Ключ Gonka был «на паузе»

Ключ создали, но он не работал: в панели Gonka он стоял в статусе «на паузе», пока его не включили. Урок: после создания ключа загляни в панель провайдера и проверь, что ключ активен (а иногда нужно ещё подтвердить телефон по SMS).

13. Gemini, SambaNova и OpenRouter: что не подошло

Ключ Gemini оказался не из Google AI Studio — правильный ключ начинается с AIza. К тому же Gemini блокирует регион даже через VPN. SambaNova просит привязать карту. Поэтому обоих убрали из цепочки. А у OpenRouter часть бесплатных моделей (например, Nemotron) работает, только если разрешить их на странице приватности. Урок: «бесплатно» не значит «работает сразу» — проверяй формат ключа, регион и настройки аккаунта.

14. «Кончились токены», а на самом деле выключен VPN

Hermes стал отвечать медленно и хуже, и показалось, что закончились токены. На самом деле токены были на месте: просто был выключен VPN, Gonka и OpenRouter не отвечали (таймаут), и цепочка free-chain сама переключилась на запасной Z.ai GLM-4.5-Flash — он работает без VPN, но медленнее и слабее. Урок: прежде чем думать о токенах, проверь, какая модель реально ответила и доходит ли интернет до провайдеров — по шагам из раздела «🩺 Hermes тупит».

15. Hermes стёр ключи из .env и испортил config.yaml

Hermes попросили настроить Telegram, и он сам полез править свои файлы ~/.hermes/.env и ~/.hermes/config.yaml: ключи пропали, настройки сломались. Пришлось чинить вместе с папой. Урок: не проси Hermes править его собственные .env и config.yaml. Для настройки есть hermes setup, для проверки — hermes doctor. Перед любой правкой делай копии: 

cp ~/.hermes/.env ~/.hermes/.env.bak-$(date +%Y%m%d-%H%M)
cp ~/.hermes/config.yaml ~/.hermes/config.yaml.bak-$(date +%Y%m%d-%H%M)
Если всё-таки сломалось — верни файл из последней .bak-копии (cp в обратную сторону), запусти hermes doctor и скажи папе.

16. Переполнение контекста: 32.8K / 32.8K

Разговор стал таким длинным, что не влез в «память» модели: у запасной модели окно всего около 32 тысяч токенов, и Hermes упёрся в потолок. Урок: одна задача — одна сессия. Перед новой порцией работы начинай чистый разговор командой /new, а если разговор затянулся — сожми его командой /compress.

17. Бесплатный лимит Gonka кончился (−79 тыс. токенов)

В кабинете Gonka появилось «Бесплатный тариф исчерпан, доступно −79 тыс. токенов». Ничего страшного: Hermes работает через цепочку моделей. Цепочка (free-chain в OmniRoute) — это список моделей по очереди: если первая не ответила или у неё кончился лимит, OmniRoute сам берёт следующую. Gonka мы просто переставили в конец. Без VPN из России сейчас работает только Z.ai — медленнее, но для спецификаций и коммитов хватает. С Happ (Tailscale в исключениях) — быстрее. Урок: бесплатные лимиты кончаются — поэтому в цепочке всегда несколько провайдеров.

18. Git: commit — это ещё не push

Несколько раз правки были сделаны и даже закоммичены, а на GitHub их не было: не сделан push, или он завис без VPN. А один раз коммит попал в старую ветку, которую уже смержили. Урок: всегда три шага: git add → git commit → git push. Потом проверь: 

git status -sb
Если в первой строке есть слово ahead — push не дошёл. Если git push висит — включи Happ и повтори. Для каждой новой работы — новая ветка: git switch -c spec/имя-работы. PR создаётся на GitHub кнопкой «Compare & pull request» («Сравнить и отправить запрос на слияние») в жёлтой плашке. Если список pull requests пуст — значит PR ещё не создан.

19. openspec validate прошёл, а ошибки остались

openspec validate --all --strict проверяет только формат: заголовки, слова SHALL/MUST в требованиях, что у каждого требования есть сценарий. Смысл, опечатки, противоречия между файлами и случайно стёртые строки он не видит. Поэтому спецификация и прошла 5 раундов ревью. Урок: «зелёный» validate — это хорошо, но после него всё равно нужно прочитать изменения самому и показать папе.

Пишем код порциями (apply) Текущий этап

Спецификация смержена — теперь Hermes пишет код по tasks.md. Главное правило: не всё сразу, а по 5–6 задач. Так проще проверить, и ничего не потеряется.

Один раз перед стартом создай ветку для кода:

cd ~/eatandfit && git switch master && git pull && git switch -c feat/auth-and-consent

Дальше для каждой порции:

  1. В Hermes: /new, потом /openspec-apply-change add-auth-and-consent и напиши, какие задачи делать, например «сделай задачи 1.6–1.8».
  2. Проверь, что всё собирается: npm run build и npm start в папке backend.
  3. Убедись, что сделанные задачи отмечены в tasks.md как - [x] 1.6 ….
  4. git add backend openspec — только нужные папки. Никогда не добавляй .env и .hermes/ (там ключи); обе строки должны быть в .gitignore. Проверь git status.
  5. git commit -m "feat: tasks 1.6-1.8" и git push, потом git status -sb — без слова ahead.
  6. Напиши папе — он сделает ревью.

PR для кода (PR #5) открыт до конца работы и обновляется сам после каждого push. Мержим в самом конце, когда все задачи сделаны и проверены.
